# MMD ダンス

[English](mmd-dance.md) | [简体中文](mmd-dance.zh-CN.md) | **日本語**

コンパニオン UI は、MMD ダンス（`.vmd` モーション）をメモリ上で 6 台の仮想デバイスへリアルタイム再生できます。Blender と MMD Tools が実際のモデルに対して正確な FK/IK 計算を行い、UI がハードコードされたリグへの小規模なリマッピングを行って、他のポーズと同様に UDP で 60 Hz のストリーミングを行います。

UI のメイン操作領域の右列にある **Dance (MMD)** ボタンから利用できます。小さなダイアログが開くので、VMD とモデルを選び、**Analyze**、続いて **Play** をクリックします。

## 必要なもの

- **Blender**（`C:\Program Files\Blender Foundation\Blender *`、Microsoft Store の `blender-launcher.exe` アプリ実行エイリアス、`ANYADANCE_BLENDER` 環境変数、または `PATH` から自動検出）
- **MMD Tools**（[MMD-Blender/blender_mmd_tools](https://github.com/MMD-Blender/blender_mmd_tools)）。Blender のアドオン／拡張機能としてインストールしてください（`%APPDATA%` 以下の Blender 拡張機能ツリーから自動検出）
- **VMD** モーションファイル
- モーションの対象となる **PMX/PMD モデル**。MMD モデルはそれぞれ独自のライセンスを持つ第三者の著作物なので、ご自身で用意してください。ダンスの制作時に使われたモデルを選ぶと、最良の結果が得られます

## 仕組み

```text
.vmd + .pmx
  -> Blender + MMD Tools でインポートし、FK/IK/制約を評価       (scripts/blender_export_mmd.py)
  -> ワールド空間の関節ポーズを含む単一の solved-motion JSON   (src/core/solved_motion.*)
  -> ハードコードされた 6 台のデバイスへ簡易リマッピング       (src/core/mmd_retarget.*)
  -> ドライバーへ 60 Hz の UDP ストリーム                       (UI の通常経路)
```

`scripts/blender_export_mmd.py` は Blender 内でヘッドレス実行されます。モデルとモーションをインポートし、MMD Tools にポーズを評価させて、**1 つ**の JSON ファイル（エクスポートのたびに再利用／上書きされる `%TEMP%\AnyaDance\mmd_solved.json`）へ、各フレームの頭、肩、肘、手首、骨盤、足首、つま先のワールド空間ポーズと、左右の手指の曲げ量を書き込みます。モデルに必要な指ボーンがある場合は、コントローラー座標系のキャリブレーション用に、レスト時の各手の指方向と手のひらの法線も記録します。出力の規約はドライバーと同じです。右手座標系、`+Y` が上、`-Z` が前、単位はメートル、クォータニオンは `xyzw`、アバターの左側は `-X` です。

## 簡易リマッピング

リグはハードコードされ、旋回はジョイスティックで行うため、リマッピングもそれに応じて小規模です（`src/core/mmd_retarget.cpp`）。

- **旋回 → ジョイスティック。** リマッピングはワールド内の方向操作をコントローラー入力として維持します。通常のポーズストリーミングと同じ `Q`／`E` 操作で、ワールド内のアバターの向きを変えます。
- **身長に合わせてスケーリング。** 立位の身長が目標身長（`1.5 m`、リグの HMD 高さ `kResetHmdY`）に一致するよう、身体全体をスケーリングします。
- **デバイスを直接配置。** 各デバイスは駆動元の関節に追従します。HMD ← 頭（頭頂へ少し移動）、腰 ← 骨盤、足 ← 足首、手 ← 手首です。手のひらのオフセットは手首ローカルのレスト空間でキャリブレーションされるため、実際の手首の屈曲に追従します。また、VRChat IK が腕を伸ばしたターゲットを得られるよう、肩を中心として少し伸長されます（**Hand reach**）。
- **HMD／腰／足の回転は差分として適用。** 関節の回転をモデルのレストポーズからの相対値として、直立して前を向くきれいなデバイスのレスト状態へ適用します。これにより、これらのデバイスは安定したレスト座標系を保ちます。
- **計算済み手首からコントローラーの向きを決定。** モデル固有の手首ボーン座標系をレスト時の OpenVR コントローラー座標系へ合わせた後、計算済みの手首へ剛体として追従させるため、屈曲、橈尺屈、ロールがすべて保持されます。エクスポートされたレスト時の指／手のひら軸が手のひらの絶対ロールを設定し、肩／肘／手首の解剖学的配置が関節に基づくレスト位置合わせを提供します。
- **指。** モデルに指ボーンがある場合、左右の手指の曲げ量がコントローラーのスケルタルハンドポーズを駆動します。

固定位置：Play を押すとダンスは HMD の現在の X/Z 位置へ固定されるため、アバターはその場で踊ります。

## ダイアログ

| 項目 | 意味 |
|------|------|
| VMD motion | `.vmd` ダンスファイル。 |
| Model | 計算に使用する `.pmx`／`.pmd` モデル。 |
| Loop | ダンス終了時に繰り返します（オフの場合は最後のポーズを維持）。 |

それ以外（目標身長 `1.5 m`、再生速度、手の到達距離、計算フレームレート）には固定の既定値を使用します。

折りたたみ式の **Advanced** には **Blender path** と **MMD Tools path** があります。ダイアログを開くと検出した場所が自動入力されるため、通常はその値を使用します。手動で指定したパスは UI の設定へ保存され、次回起動時にも再利用されます。

**Analyze** は Blender による計算を実行し、長さ、フレーム数、スケールを表示します。計算が成功するまで（および計算の実行中）、**Play** は無効です。有効になった **Play** を押すと計算済みのダンスを再生します。**Stop** は T ポーズへ戻します。**Reset to T-Pose** でも再生を停止します。

## クリップ（.nya）の保存と読み込み

ダンスの解析後、**Save .nya** を押すとリターゲット済みの結果が `.nya` クリップファイルへ書き込まれます。**Load .nya** はクリップを読み込み、すぐに Play を有効にします。クリップの読み込みでは Blender による計算とリマッピングの両方を省略するため、保存済みのダンスは後の実行時に即座に再生できます。

`.nya` ファイルはデバイスレベルのフレーム（6 台のデバイスポーズと左右の手指の曲げ量）を保存します。そのため、メインウィンドウの **Save Pose**／**Load Pose** と同じ形式であり、ポーズは 1 フレームだけのクリップです。読み込み時には、デバイスの Y 座標が HMD では 0–25 m、他の 5 台では -30–25 m に、指の曲げ量が `[0, 1]` にクランプされます。`src/core/nya_format.*` を参照してください。

## 実行時の動作

- 長いダンスの初回計算には、Blender で数秒から 1 分ほどかかることがあります。処理中も UI は描画を続け、T ポーズをストリーミングします。
- リターゲット品質は、モーションとモデルの体格がどの程度一致しているかによって決まります。
- この機能はオフライン計算＋ライブ再生です。計算済みのモーションを UI が再生に使用します。プロジェクトの[免責事項](../DISCLAIMER.md)に記載された、一般的な VRChat のアンチチートに関する注意事項が適用されます。
