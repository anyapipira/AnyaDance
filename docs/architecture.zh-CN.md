# 架构

[English](architecture.md) | **简体中文**

AnyaDance 由三个运行时部分组成：

1. `anyadance_core`：无外部依赖的 C++17 逻辑，由驱动、测试界面与测试共享。
2. `driver_anyadance.dll`：由 SteamVR 加载的 SteamVR/OpenVR 服务端驱动。
3. `AnyaDance.exe`：基于 Dear ImGui 的 Win32/DX11 测试发送端。

## 核心库

核心库拥有数据结构与可测试的行为：

- 设备常量与公共标识符
- 向量/四元数辅助函数，线缆姿态使用 XYZW 顺序的四元数
- UDP 协议解析与序列化
- 驱动命令日志协议的解析与序列化
- `0 <= Y <= 25.0 m` 安全钳制
- 规范化 T 姿势重置
- 键盘输入映射（每个按键直接映射到一个按住的按钮或轴）
- 鼠标操控运算
- 日志环形缓冲区与操控合并

## 原生驱动

SteamVR 驱动最多注册六个设备：

- 头显（HMD）
- 左、右 `knuckles` 控制器
- 髋部、左脚、右脚通用追踪器

驱动在 `127.0.0.1:39570` 上启动一个回环 UDP 接收器。有效的样本会更新各设备的姿态状态，无效数据包将被忽略。作为纵深防御，驱动在数据包校验后会再次钳制设备 Y。每次解析后，接收线程都会通过非阻塞 UDP 套接字向回环多播组 `239.255.39.71:39571` 发送一份带版本号的命令报告。多播组与端口可通过驱动设置配置，接口与 TTL 则确保报告只在本机传递。多个本机应用进程可加入该组，且不会增加驱动的发送次数。

所有设备都以中性姿态开始且保持有效，即使数据包停止也仍然有效。驱动将最近接受的姿态报告为已连接、有效且 `TrackingResult_Running_OK`。

## 测试 UI

伴随 UI 包含 UI 线程、推流线程以及可选的驱动日志监听线程。UI 线程负责 ImGui 渲染、聚焦时的键盘轮询以及鼠标操控。推流线程复制同步后的状态，每帧序列化一次，并以 60 Hz 发送完整的六设备帧。**监视驱动命令** 开关可在运行时加入或离开日志多播组。监听器加入期间，已接受和已拒绝的驱动报告会进入现有日志，UI 自身的成功发送记录会被抑制。60 Hz 的成功报告会按 100 毫秒显示窗口合并，以限制日志渲染开销。
