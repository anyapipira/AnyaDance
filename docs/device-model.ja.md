## デバイス

```text
anyadance_hmd_001                    HMD
anyadance_left_controller_001        左コントローラー
anyadance_right_controller_001       右コントローラー
anyadance_hip_001                    汎用トラッカー
anyadance_left_foot_001              汎用トラッカー
anyadance_right_foot_001             汎用トラッカー
```

コントローラーはコントローラー種別として `knuckles` を通知し、`{indexcontroller}` を介して Valve Index のレンダーモデルを使用します。入力プロファイルは公開の `{anyadance}` リソース名前空間に置かれています。また `/output/haptic` コンポーネントも公開するため、SteamVR はハプティック要求をこれらのコントローラーへルーティングします。ドライバーにモーターはなく、実際の振動は再生しませんが、各要求をドライバーロググループへレポートします（[protocol.ja.md](protocol.ja.md) を参照）。

## T ポーズの定数

コンパニオン UI は標準テスト用 T ポーズで起動し、リセット時にもそのポーズへ戻ります。次の HMD ローカル座標のオフセットは、意図的に一か所へ集約され、テストで調整できるようになっています。

```text
HMD の Y:          1.50 m
左コントローラー:  (-0.68, -0.17, -0.10) m
右コントローラー:  ( 0.68, -0.17, -0.10) m
腰:                ( 0.00, -0.43, -0.05) m
左足:              (-0.09, -1.24,  0.10) m
右足:              ( 0.09, -1.24,  0.10) m
```

ニュートラルな HMD が `(0.00, 1.50, 0.00)` にある場合、コントローラーは `(-0.68, 1.33, -0.10)` と `(0.68, 1.33, -0.10)`、足は `(-0.09, 0.26, 0.10)` と `(0.09, 0.26, 0.10)` に配置されます。

リセットすると HMD は回転なしで `(0.00, 1.50, 0.00)` に固定され、中央に位置して正面を向くリグになります。他のデバイスの位置には上記のオフセットを使用し、コントローラーの回転には次の標準値を使用します。

```text
左コントローラー: (0.0, 0.0, -0.7071067811865475, 0.7071067811865475)
右コントローラー: (0.0, 0.0,  0.7071067811865475, 0.7071067811865475)
```

腰と足には回転なしの値を使用します。

## 仮想 HMD の表示

仮想 HMD は既定で `1920x1080` のデスクトップウィンドウと、片目あたり `1920x1080`、アスペクト比 `16:9` の推奨レンダーターゲットを通知します。既定の `left` アイモードでは片目の画像がウィンドウ全体を占めます。`both` モードではウィンドウを 2 分割し、それぞれの領域で `16:9` の片目画像をレターボックス表示します。ドライバーを再ビルドしなくても、`driver_anyadance` 設定セクションの `headset_window_width`、`headset_window_height`、`headset_render_width`、`headset_render_height`、`headset_window_eye_mode`、`headset_window_preserve_aspect` を使って、デスクトップウィンドウと片目あたりのレンダーターゲットを SteamVR 設定から上書きできます。上級ユーザーはコンポジターの描画負荷が約 4 倍になる代わりに、レンダーターゲットを 4K（`3840x2160`）まで引き上げられます。どのアスペクト比も使用できます。投影は設定したレンダー解像度に適応するため、画像は引き伸ばされません。

## ツールのミラー操作

コンパニオン UI には、左右のコントローラーボックスの間と左右の足ボックスの間に、それぞれミラー用チェックボックスがあります。有効にすると、片側をドラッグしたときに反対側が絶対座標で反射したポーズになります。HMD 座標系モードでは、現在の HMD のヨーと位置によって定義されるローカル YZ 平面を基準に反射します。Global 座標系モードでは、HMD の位置を中心としてワールド軸を使用します。これにより、ドラッグの差分だけをコピーまたは反転するのではなく、左右のペアが対称に保たれます。

キャプチャーパネルには固定高さのマウスヘルプ領域が確保されているため、言語を切り替えてもデバイス行の位置は変わりません。各ボックスはパネルの高さに合うようにサイズ調整されます。HMD 以外のデバイスでは、左ドラッグでローカル X/Y 方向へ移動し、中ドラッグで回転、右ドラッグで奥行き方向へ移動します。HMD は回転に加えて、右ドラッグ（左＋右の同時ドラッグでも可）で垂直方向（Y）へ移動できます。デバイスの Y 座標の上限は `25 m` ですが、下限があるのは HMD だけです。HMD は `0 m` で止まり、他の 5 台は地面より下の `-30 m` まで移動できます。パネルの空いている領域では、中ドラッグで HMD の位置を中心にリグ全体をヨー／ピッチ回転し、中＋右ドラッグでロール回転、右ドラッグだけでリグ全体を垂直移動します。リグはどちらかの Y 境界で一体として停止し、下方向では HMD が `0 m` に達した時点で止まります。

パネルの空いている領域を左ドラッグすると、右コントローラーのサムスティックを操作できます。押し始めた位置がニュートラルの中心となり、ドラッグのオフセットが ±1 にクランプされたスティック軸へマッピングされ、離すと中央に戻ります。これは `M` を押し続けて表示する右手用クイックメニューの照準操作を意図しています。

## ツールのログ

コンパニオン UI は、選択中の UI 言語に関係なく UDP ログを英語で保持します。**Monitor driver commands** を有効にすると、ドライバーの処理レポートを受け取るためにループバックマルチキャストグループ `239.255.39.71:39571` へ参加します。この設定は UI の実行中にも切り替えられます。初期状態はオフで、選択内容は次回起動時にも保持されます。他のローカルプロセスも同じグループへ同時に参加できます。ドライバーレポートには、元の送信元エンドポイント、受理または拒否の結果、処理の詳細、元のコマンド JSON が表示されます。監視中はドライバーレポートがコマンド成功の行を提供し、UI 自身の送信成功行は抑制されます。ログ行の任意の部分へポインターを合わせると JSON が表示されます。行をクリックすると強調表示され、スクロール可能な JSON ビューを持つ固定詳細ウィンドウが開きます。強調表示中の行をもう一度クリックすると詳細ウィンドウが閉じます。

## ローカライズ

UI の文字列は `src/ui/localization.*` にあります。1 文字列につき 1 行のテーブルが、利用可能な言語をコードと表示名とともに定義しています。UI の描画処理はこのテーブルを反復し、UDP ログのラベルは意図的に英語の文字列を使用します。
