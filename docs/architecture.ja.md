# アーキテクチャ

[English](architecture.md) | [简体中文](architecture.zh-CN.md) | **日本語**

AnyaDance は、実行時には次の 3 つの部分で構成されます。

1. `anyadance_core`: ドライバー、UI、テストで共有される、依存関係のない C++17 ロジック。
2. `driver_anyadance.dll`: SteamVR によって読み込まれる SteamVR/OpenVR サーバードライバー。
3. `AnyaDance.exe`: Dear ImGui を使用した Win32/DX11 コンパニオン UI。

## コアライブラリ

コアライブラリは、データ構造とテスト可能な動作を担います。

- デバイス定数と公開識別子
- 通信上のポーズに XYZW クォータニオンを使用するベクトル／クォータニオンヘルパー
- UDP プロトコルの解析とシリアライズ
- ドライバーコマンドログプロトコルの解析とシリアライズ
- デバイスごとの Y 座標の安全クランプ（HMD は `0 <= Y <= 25.0 m`、それ以外は `-30.0 <= Y <= 25.0 m`）
- 標準 T ポーズへのリセット
- キーボード入力マッピング（各キーを押下中のボタンまたは軸へ直接マッピング）
- マウス操作の計算
- ログのリングバッファと操作ログの集約

## ネイティブドライバー

SteamVR ドライバーは最大 6 台のデバイスを登録します。

- HMD
- 左右の `knuckles` コントローラー
- 腰、左足、右足の汎用トラッカー

ドライバーは `127.0.0.1:39570` でループバック UDP レシーバーを起動します。有効なサンプルはデバイスごとのポーズ状態を更新し、無効なパケットは無視されます。多層防御として、ドライバーは検証後にデバイスの Y 座標をクランプします。地面より上に維持されるのは HMD だけなので、範囲は HMD が `0–25 m`、それ以外の 5 台が `-30–25 m` です。レシーバースレッドは解析を試行するたびに、ノンブロッキング UDP ソケットを介してループバックマルチキャストグループ `239.255.39.71:39571` へ、バージョン付きのコマンドレポートを 1 件送信します。グループとポートはドライバー設定で変更できますが、インターフェイスと TTL により配信はローカルマシン内に限定されます。複数のローカルアプリケーションプロセスが同じグループに参加しても、ドライバーの送信処理は増えません。レポートはコマンドが直前にレポートしたものと異なる場合にだけ送信されるため、保持中のポーズがストリームレートで繰り返されることはありません。`RunFrame` は SteamVR のイベントキューも処理し、2 台のコントローラーへのハプティック要求を同じグループへレポートします。この送信には別のソケットを使用するため、RunFrame スレッドがレシーバースレッドとソケットを共有することはありません。

すべてのデバイスは有効なニュートラルポーズで開始し、パケットが停止しても有効なままです。ドライバーは最後に受理したポーズを、接続済み、有効、かつ `TrackingResult_Running_OK` として報告します。

## UI

コンパニオン UI には UI スレッド、ストリーミングスレッド、および任意で有効にできるドライバーログリスナースレッドがあります。UI スレッドは ImGui の描画、ウィンドウがフォーカスされている間のキーボードポーリング、およびマウス操作を担います。ストリーミングスレッドは同期された状態をコピーし、フレームごとに 1 回シリアライズして、6 台すべてのデバイスを含むフレームを 60 Hz で送信します。**Monitor driver commands** スイッチを使うと、実行中にログ用マルチキャストグループへ参加または退出できます。参加中は、受理および拒否されたドライバーレポートが既存のログへ入り、ローカル送信成功の行は抑制されます。60 Hz で届く受理済みレポートは 100 ms の表示ウィンドウに集約され、ログ描画の負荷が一定範囲に抑えられます。
